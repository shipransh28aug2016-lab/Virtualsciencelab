# GURU — Contract (binding for all module authors)

Product: **Guru** — recursive, self-learning, bilingual (Hindi/English), voice+text AI work-bot for a CBSE teacher/ed-tech developer.
Zero runtime deps, vanilla ES modules, browser-first, **every module must also `import` cleanly under Node ≥18 (no top-level DOM/window access; guard with `typeof window`)**. Runs as static site (GitHub Pages) + installable PWA + Android (Capacitor/TWA). Offline works without any API key (local engine); online with a key = full LLM power.
Root: `guru/`. Each agent owns ONLY its listed paths. Never edit another owner's files; request via a short note in your final report.

## Module protocol
Every `src/<mod>/index.js` exports `export async function register(k)`; `k` (kernel API):
- `k.bus` — `{on(evt,fn)→off, emit(evt,payload), once}`
- `k.tools.register({name, description, schema /*JSONSchema object*/, run: async (args, ctx)=>any, tags?:[]})`; `k.tools.call(name,args,ctx)`; `k.tools.list()`
- `k.agents.register({id,name,role,description,system,tools:[toolNames],tier:'fast'|'smart'})`
- `k.intents.register({id, tool, patterns:[RegExp], extract:(text,lang)=>args, examples:[str]})` — offline router (en+hi patterns, Devanagari + Hinglish)
- `k.services.set(name,obj)` / `k.services.get(name)` / `k.services.has(name)`
- `k.config` — `{get(key,def), set(key,val)}` persisted (localStorage; in-memory under Node)
Failures in one module must never break boot: kernel `import()`s each module in try/catch and reports to bus `module:error`.

## Services (name → shape)

Providers: `anthropic`, `openai` (any OpenAI-compatible baseUrl), `gemini`, `local` (offline, uses `k.intents`, templates; always available, default when no key).
- `memory`: `remember({kind:'fact'|'pref'|'episode'|'skill'|'lesson', text, tags?, meta?, weight?}) → id`; `recall(query,{k=6,kind?}) → [{id,text,kind,score,meta}]`; `forget(id)`; `feedback(runId,{score:-1|0|1|2..5,note?})`; `profile() → {name,role,langPref,subjects,classes,style,stats}`; `reflect(runRecord) → lessons[]` (distils lessons, updates skill stats/preferences); `export() → JSON`; `import(json)`. Backed by IndexedDB (fallback: in-memory Map under Node). Retrieval = BM25 over Unicode tokens (Devanagari-aware) + recency/weight boost. Seed profile memory (see `src/memory/seed.js`): user is a CBSE teacher & edtech developer (Commerce/Physics/Chemistry XI–XII, virtual labs, bulk marksheets, case studies, syllabus verification), works Hindi+English, wants minimal UI, max capability.

- `files`: `read(input /*File|Blob|ArrayBuffer|Uint8Array*/, nameOrMime) → Promise<{format, text, sheets?, slides?, pages?, meta}>` for `txt,md,csv,json,html,docx,xlsx,pptx,pdf(best-effort text extraction),png/jpg(meta only)`; `write(format, spec) → Promise<{blob, filename, mime}>` for `docx,xlsx,pptx,pdf,md,csv,html,json,zip`; `edit(blobOrBytes, format, ops) → {blob}` (docx: replace text/append paragraphs/tables; xlsx: set cells/add sheet/formulas; pptx: add/replace slides; md: patch); `zip` util `{create, read}` (own STORE+DEFLATE via CompressionStream/DecompressionStream, CRC32).

Hindi (Devanagari) must render correctly in every format (docx/pptx: set `w:rFonts`/latin+cs fonts "Noto Sans Devanagari"/"Mangal"; pdf: canvas-rasterised pages when DOM exists, else Latin-only built-in).

llm: `llm_status` · memory: `memory_remember`, `memory_recall`, `memory_forget`, `memory_profile` · voice: `speak` · files: `file_read`, `file_write`, `file_edit` · connectors: `drive_list`, `drive_search`, `drive_read`, `drive_write`, `local_pick`, `local_save`, `github_get`, `github_put`, `web_fetch`, `web_search` · cbse: `cbse_syllabus`, `cbse_blueprint`, `cbse_question_paper`, `cbse_practice_set`, `cbse_study_material`, `cbse_marking_scheme`, `cbse_case_study`, `cbse_assertion_reason`, `cbse_mcq_bank`, `cbse_answer_check` · kernel: `delegate` (recursion), `plan`, `critique`, `reflect`, `ask_user`, `emit_artifact({name,format,spec})` (UI shows download/save-to-drive chips), `run_js` (sandboxed iframe/worker eval for calc/transforms; Node: `vm`).
Tool `run` returns JSON-serialisable data; binary results returned as `{artifact:{filename,mime,blobRef}}` through `ctx.artifacts.add(blob,filename)` (kernel provides `ctx.artifacts`).

## Recursive orchestration (kernel)
`kernel.run(goal,{lang,signal,maxDepth=3,maxSteps=40,budgetTokens=60000,onEvent}) → RunRecord{id,goal,plan,tasks,artifacts,critique,answer,usage,lessons}`.
Loop: **Recall** (memory) → **Plan** (master "guru" decomposes into DAG `[{id,agent,task,deps}]`, JSON) → **Execute** ready tasks in parallel via worker agents (tool-use loop, each worker may call `delegate` to recurse with depth+1; depth/budget/loop-detection guards; identical-call dedupe) → **Critique** (critic agent scores 0–10 vs goal: correctness, CBSE-pattern fidelity, language, completeness) → if <8 and refinements<2 **Refine** (re-run failing tasks with critique feedback — this is the recursion on the whole) → **Synthesize** answer in user's language → **Reflect** (memory.reflect: lessons, skill stats, preference updates; persisted) . With provider `local`: same loop but plan comes from `k.intents` match, critic = rule-based validators (cbse validators), still recursion-capable on sub-tasks.
Bus events: `run:start, recall, plan, task:start, task:token, tool:call, tool:result, task:done, critique, refine, answer, artifact, run:done, run:error, module:error, ask`.
Runtime team (kernel `agents-default.js`): **guru** (master) · **planner** · **researcher** (web/drive) · **cbse-author** · **tutor** (bilingual explain, Socratic) · **file-engineer** · **drive-ops** · **coder** (web-app dev; emits html/js artifacts) · **critic** · **curator** (memory/learning).

## CBSE (`src/cbse`)
Data: reads `../../../data/curriculum/cbse-2026-27.json` when served from repo (try/catch; embedded minimal fallback in `syllabus.js`). Own built-in **blueprints** for Class X/XII/XI: Physics 042 (70+30 prac), Chemistry 043, Commerce: Accountancy 055, Business Studies 054, Economics 030, Maths 041 (+ Hindi 002/302, English 301 structure as sections only) — marks, time, section A MCQ/AR (1m), B VSA (2m), C SA (3m), D case-based (4m), E LA (5m), internal choice rules, competency-focused share encoded as configurable `pattern.competencyPct` (value from the repo curriculum JSON when present; otherwise a default flagged `verified:false` in output so the teacher confirms against the latest CBSE circular). Output Q-paper object `{header, sections:[{name,instructions,questions:[{no,marks,type,text,options?,answer,markingScheme:[{point,marks}],co?,bloom,difficulty,chapter}]}], totals}` in **English, Hindi, or bilingual** (side-by-side/stacked). Question bank is template+generator driven (numeric generators with randomised-but-valid parameters for Physics/Chemistry/Accountancy; conceptual items from curated stems) — all numerics must be computed, never hand-typed, and every generated question carries its computed answer. `cbse_answer_check` validates arithmetic & mark totals (sum of section marks = paper total; internal choice present; no duplicate stems; chapter coverage weights ±).
Exports via `files.write` : QP (docx/pdf), marking scheme (docx/pdf/xlsx), practice sets (docx/pdf + md), study notes (docx/pptx/md), flashcards (csv/xlsx).

Minimal: one column. Top bar (Guru logo, language toggle EN/हि/Mix, status dot [offline-local | online-LLM], ⚙). Chat stream with live agent-trace chips (collapsed "🧠 6 steps"). Bottom composer: text, 🎤 hold/tap voice, 📎 attach (local/Drive), send. Artifacts as chips (download · save to Drive · open). Settings drawer: provider+key, Google client ID, GitHub token, language/voice, memory (view/export/import/forget), theme. Command palette (`/` or Ctrl+K) lists tools/agents. Light/dark. Mobile-first (Android), 16px gutters, large tap targets ≥44px, RTL-agnostic, a11y labels (aria), reduced-motion. No frameworks, no CDN. Devanagari-safe fonts.
