# Guru security review (QA agent 10)

Severity: H high, M medium, L low, I info. Files are under `guru/`.

| # | Area | Sev | Finding | Owner / file | Fix |
|---|------|-----|---------|--------------|-----|
| 1 | run_js (Node) | H | `vm` sandbox escape: host-realm objects leak `Function`. Repro: `run_js {code:"return console.log.constructor('return process.version')()"}` returns the Node version (full RCE under Node/CLI/tests). | kernel `src/kernel/builtin-tools.js` runJsNode | Pass only frozen JSON copies; build `console` inside the context (`vm.runInContext`), or use `worker_threads` with `resourceLimits`, and treat vm as non-security. |
| 2 | run_js (browser) | M | Blob Worker uses `new Function`; CSP has no `'unsafe-eval'`, so it will be blocked (feature broken). If eval were allowed, worker can still `fetch` any https (CSP `connect-src https:`), so LLM-written code could exfiltrate data. | kernel `builtin-tools.js`; `index.html` CSP | Run in sandboxed iframe (`sandbox="allow-scripts"`, own CSP `connect-src 'none'`) via srcdoc/blob. |
| 3 | Key storage | M | Without passphrase API keys are only base64 in localStorage (documented in `src/llm/keys.js`). XSS or any extension reads them. Encrypted mode (PBKDF2 210k + AES-GCM, AAD=provider) is sound. | llm `src/llm/keys.js`; UI settings | Default-prompt for a passphrase; warn in UI when unencrypted. GitHub PAT / Google client id stored through config (plain). |
| 4 | Zip bomb | M | `zip.read` limits total by *declared* sizes from the central directory, which the attacker controls; `inflateRaw` fully expands before the size check. A small zip can exhaust memory. | files `src/files/zip.js` ~L97-109 | Stream inflate with a hard cap = declared size (abort at cap), cap per-entry (e.g. 64MB), cap entry count. |
| 5 | Zip-slip | L | Entry names are only used as map keys, never written to a filesystem, so no slip today. `localfs`/zip "extract" features must sanitise `..`, absolute paths and `\`. | files `zip.js` | Add `safeName()` helper now. |
| 6 | Web SSRF | L | Good: https only, no userinfo, IPv4/IPv6/NAT64/6to4/numeric forms blocked, redirect target revalidated. Gap: validation of redirects happens after the request was sent (browser follows redirects), so a blind GET to an internal host is possible; no DNS-rebinding defence (not feasible in browser). User-set `searchUrl` allows http. | connectors `src/connectors/web.js` ~L228, L257 | Use `redirect:'manual'` where not opaque; require https for searchUrl. |
| 7 | Markdown XSS | I | `src/ui/md.js` builds DOM via textContent, links limited to http(s)/mailto, `rel=noopener`. No innerHTML/eval/document.write found in `src`. Pass. Note bare-URL regex and `[x](https://..)` accept any https target (phishing only). | ui | none |
| 8 | CSP | L/M | Meta CSP is strong (no inline script/style, `object-src 'none'`, `base-uri 'none'`). Weak points: `connect-src https:` (exfil if XSS), `'wasm-unsafe-eval'` unused?, `frame-ancestors` is ignored in meta (clickjacking) - add header via host (GitHub Pages cannot) or frame-buster. | `index.html` | Tighten connect-src to known API hosts + user-configured origins at runtime; drop wasm-unsafe-eval if unused. |
| 9 | OAuth scopes | M | Default requests `drive.readonly`, `documents`, `spreadsheets`, `presentations` in addition to `drive.file`: broad read of the whole Drive. | connectors `src/connectors/gdrive.js` L7-14 | Default to `drive.file` only; request others incrementally (include_granted_scopes) when a feature needs them. Destructive ops are already gated by `confirmed:true` (verified in integration test 6). |
| 10 | Prototype pollution (JSON import) | L | Memory import uses `JSON.parse` + Map store; no `Object.assign` into prototypes found. Imported `meta` keys such as `__proto__` become own keys but are stored in a Map. Imported records are trusted (no kind/length validation) so an import can plant persistent *prompt-injection* memories. | memory `src/memory/store.js` L103-118 | Validate kind enum, cap text length, strip control chars; mark imported items `meta.imported`. |
| 11 | SW share-target abuse | M | `POST /share-target` accepts any cross-site form POST, no size/MIME/count cap; files cached under `guru-share-inbox-v1` and later ingested. Attacker page can stuff cache or feed crafted docs to parsers. Filename is URI-encoded (good). | `sw.js` handleShare | Cap files (count, 20MB), allowlist MIME as in manifest, require user confirmation before ingest, TTL-clean the inbox. |
| 12 | SW cache poisoning | L | Navigation handler stores any `res.ok` navigation as `index.html` (e.g. a different path/query returning HTML). SWR caches same-origin `src/` so a one-time compromised response persists until next version. API hosts and cross-origin are never cached (good). | `sw.js` fetch handler | Cache only when `url.pathname` is the app shell; verify `res.type==='basic'`. |
| 13 | Drive/test token | I | Tests inject a token with `connectors.get('gdrive').setToken(t)` (no config keys). `setToken` is public API on the connector; do not expose via tools. | connectors | none |

Untrusted-content note: web_fetch/file_read text flows into LLM prompts; tool outputs should be wrapped as data and destructive tools (`drive remove/overwrite`, `github_put`) must keep requiring UI confirmation.
